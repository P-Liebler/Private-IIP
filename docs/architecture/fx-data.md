# P3 FX data

Manual CSV accepts positive dated CHF, EUR and USD pairs with explicit base, quote and rate. `fx_rates` holds the selected rate; `fx_rate_versions` keeps its source, raw reference, local timestamps and rule versions. `GET /api/v1/fx/rate` returns direct, inverse or one-bridge cross rates, with the contributing version IDs, rate dates and sources. Same-currency conversion is an explicit derived identity rate. A missing rate returns `UNAVAILABLE`, never zero.

Carry forward is limited to `FX_MAX_CARRY_DAYS` calendar days (default 5, configurable 0–10). The response exposes `rate_date`, `carry_days`, `carried_forward` and conversion direction. Each leg of a cross must separately meet that limit and `as_of` visibility. This is a local calendar-day policy; a market-specific holiday calendar and fixing-time proof are future refinements, so a date alone is not evidence of a specific intraday availability time.

The ECB collector is implemented for the documented daily `EXR/D.CHF+USD.EUR.SP00.A` SDMX CSV series. It checks the existing rights gate and Valkey limit before HTTP, stores exact response bytes before parsing, verifies the CSV dimensions and then enters the same FX version service. It is disabled until an operator documents rights and enables the source; tests use `MockTransport` only. The SNB connector checks the gate but fails with `SOURCE_FORMAT_UNVERIFIED` even after enablement. The officially located [SNB FX cube](https://data.snb.ch/en/topics/ziredev/cube/devkum) is monthly, so it cannot be used as a daily rate. A verified daily series and response contract are required before implementing its parser. The [SNB API guidance](https://data.snb.ch/en/help_api) also recommends `lastUpdate` or ETag rather than polling the full data endpoint. Sources checked 2026-10-12; [ECB API examples](https://data.ecb.europa.eu/help/api/data-examples) and [EXR format](https://data.ecb.europa.eu/help/api/data).
