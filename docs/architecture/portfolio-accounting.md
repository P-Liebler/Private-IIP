# Portfolio Accounting (P4)

The transaction ledger is the accounting source of truth. `portfolios` belong to one user; accounts belong to one portfolio. All portfolio routes require the session user and check ownership. A portfolio or account can be archived without deleting its history. Transactions are immutable economic facts except for their `ACTIVE`/`VOIDED` state. A correction voids the old row and appends a replacement linked by `replaces_transaction_id`; audit events identify both operations. Historical `as_of` replay uses `created_at` and `voided_at`.

`PortfolioEngine.ledger_state` replays transactions in trade-date order with `Decimal` and 34-digit working precision. Money is rounded half-even to eight decimals at cash and basis posting boundaries. V1 uses weighted average cost per account and instrument. Buy fees and taxes enter basis and reduce cash. A sell removes the proportional average basis; sale fees and taxes reduce proceeds and realized P/L. Overselling raises `INSUFFICIENT_POSITION`. Negative cash is kept. Split ratio changes quantity without changing basis; a ratio requiring more than eight share decimals requires manual review. Dividends and interest raise cash and income, net of recorded withholding.

Corporate actions are applied explicitly via `/portfolios/{id}/corporate-actions/apply`. The application table has a unique account/instrument/date/type key. Split and dividend effects become system transactions referencing the canonical version. A repeated application returns the existing result; a revised canonical version requires explicit correction review. A manual same-date effect blocks automatic application. The valuation reports eligible unapplied actions as `UNVERIFIED_CORPORATE_ACTION`. A delisting or ticker change is recorded as a reviewed application without inventing a cash effect. Raw close plus explicit validated actions remains the return policy from ADR-005.

`PortfolioValuationService` uses the P3 point-in-time accepted price versions and P3 FX service. Cash, holdings, price date, age, source, version, quality and FX legs are returned. Prices older than seven calendar days are `STALE_PRICE`; missing prices or FX produce `PARTIAL`, a null total and visible issues. A known subtotal is labelled as such, never substituted for the full value. Native values stay visible when CHF/EUR/USD conversion is unavailable. Realized P/L, income, fees and taxes are translated at the relevant event date when P3 FX exists. Open basis and unrealized P/L use the valuation-date FX and are named accordingly. Missing event-date FX leaves those analytics null without changing an otherwise known current market value.

`cash_balances`, `position_snapshots` and `portfolio_snapshots` are derived read layers. Rebuilds hash the transaction IDs, accepted price versions, FX provenance and issues. Identical inputs reuse a snapshot; corrected inputs append a new one. The ledger and P3 versions remain authoritative. Transaction CSV preview stores exact raw bytes before parsing. A commit checks raw SHA-256, user/portfolio/account binding, source gate, row validation and duplicates again, then commits all rows atomically.

V1 limits: stock and ETF accounting uses one native currency per instrument; no broker API, short selling, cash in lieu or autonomous execution. Transfers are treated as external flows until linked account-to-account transfers are modeled. Delisting settlement and corrected corporate-action compensation require an explicit operator review.

An existing manual split/dividend may be linked explicitly with `adopt_manual=true` after exact economic matching, including currency and confirmed dividend costs. Ambiguous/mismatching candidates fail closed. Linking creates an application reference without duplicating or rewriting the original transaction. Linked effects are protected from ordinary correction/void; changed evidence requires an explicit review. The preview exposes whether a manual candidate exists and the UI requires an explicit linking choice.

A raw close before a recorded split/dividend cannot value the state after that event. `MISSING_EVENT_PRICE` preserves the dated quote as provenance but leaves native/base market value and the total null until a close after the event is available. It also persists safely in a partial snapshot. An `as_of` before the portfolio's actual creation yields `PORTFOLIO_NOT_AVAILABLE_AS_OF`, not a fabricated historical zero.

The duplicate key is account + external ID when supplied; otherwise a normalized numeric fingerprint. Two otherwise identical trades with different broker IDs remain valid. Preview checks references and replay, including oversells, without writing transactions. CSV fields can be mapped to trade/settlement dates, account, amounts, fees, taxes, notes and instrument ID or ticker/ISIN/FIGI. The selected account must match any CSV account value; dated identifiers must resolve uniquely and agree with an explicit ID. Unknown headers open a mapping step before validation. Commit repeats these checks and rolls the entire batch back on failure.

Application locks serialize ledger writes and snapshot rebuilds on the portfolio row. Correction/void refresh the transaction after taking the lock. Snapshot dependencies include historical event FX provenance and analytic amounts as well as current prices/FX. Earlier unapplied or corrected splits block later action entitlement. A same-date split/income combination requires explicit entitlement review. A manual split/dividend is blocked if its canonical application already exists, and a manual reverse-split effect is recognized as `SPLIT` for duplicate protection.

V1 uses an economic ex-date convention for applied dividends: gross entitlement minus explicitly confirmed withholding and fees is booked on the ex-date. The protected action preview shows source, ex-date, ratio/per-share amount and ledger quantity. Dividend application fails with `ACTION_COST_REVIEW_REQUIRED` until the user confirms both costs, including an explicit zero. A repeated application with different costs requires correction review and cannot overwrite the preserved effect. This economic cash balance does not assert broker settlement timing. Payment-date receivables and automatic broker net settlement remain outside V1; source, gross amount, confirmed costs and date remain visible.
