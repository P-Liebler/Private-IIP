# P3 market data

The P3 write path is `raw_ingestion -> verified bytes -> parse -> normalize -> hard validation -> reconciliation -> append-only version -> current read model`. Manual UTF-8 CSV is the working input while external price providers remain gated. The protected `/imports` page previews prices, corporate actions and FX, shows mapping, resolved instrument and normalized sample values, and requires explicit confirmation. `commit` reloads the original object through `get_verified`; it never trusts a second upload. Invalid rows require explicit partial-import acceptance and enter `data_quarantine`. A repeated commit of the same raw rows adds no version. The legacy P2 CSV preview is still a preview only.

`price_daily` is keyed by instrument UUID and trading date. It points at the accepted `price_daily_versions` row. Versions contain the original source and raw IDs, row number, timestamps, rule versions, resolution, quality components and any replaced version. Competing sources and rejected discrepancies remain observations; they are never averaged. The current row changes only for an accepted version. Corporate actions and FX have the same current/version split. Raw bytes are immutable in MinIO; canonical versions are append-only in PostgreSQL. No consumer should read raw input as a price.

Positive OHLC values, nonnegative volume, OHLC ordering, representable decimal precision, date, currency and instrument identity are hard gates. `VALID`, `WARNING` and `REJECTED` describe validity independently of quality. Close discrepancies use `abs(a-b)/median(a,b)`: below 0.25% consistent, 0.25–0.50% notice, 0.50–2% explicit review, above 2% quarantine unless an operator explicitly resolves it with a reason. Priority can select between permitted sources; it never grants rights. Quality weights are source trust 40%, cross validation 25%, freshness 15%, schema completeness 10% and historical consistency 10%. A missing comparison gets a neutral cross-validation component of 0.5; it is not treated as corroboration. Quality labels use the master-plan thresholds: EXCELLENT ≥0.95, HIGH ≥0.85, MEDIUM ≥0.70, LOW ≥0.50 and REJECT below 0.50. A score cannot accept hard-invalid data; the quality label is diagnostic and does not change validity. Missing and stale values stay explicit in the API and data-quality page.

The protected API includes CSV preview/commit, instrument prices and price versions, corporate actions, indicative return, FX rate, ECB collection and data-quality summary. Price responses expose source, raw reference, validation, quality, source count and `known_at`. The instrument page plots only validated raw closes. Chart display converts decimal strings to JavaScript numbers; the API and database retain decimal precision.

The return endpoint applies [ADR-005](../decisions/ADR-005-price-adjustment-policy.md), but reports `PROVISIONAL` and `action_coverage=UNVERIFIED` until a later workflow can attest that the corporate-action history is complete. Portfolio accounting must not treat that provisional value as a verified total return.
